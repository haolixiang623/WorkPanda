# 2026-11-07 工作记录

## 通用 harness 第四轮：副作用账本与审计归档

- 动机：trace 有界（默认 500 条）会被淘汰，任务事件随任务归档，两者都无法回答
  "三个月前那次提交到底发出去没有"。只要流程里有非幂等工具，这个问题必须长期有答案。
- 新增 `harness/effects.py`（纯函数）：把调用记录提炼成外部动作——非幂等成功 `applied`、
  非幂等超时 `unknown`；幂等工具（含其超时）、被拦、工具自报失败一律不入账。
  参数只留 sha256 前 16 位指纹，归档里没有原始业务数据。
- 新增 `harness/audit.py`：`JsonlAuditJournal` 只追加 + 每次 fsync + 按大小滚动（保留 N 份），
  读回时坏行跳过；`NullAuditJournal` 让调用点不必判空。
- `HarnessExecutor` 增加 `audit` 参数：每次执行追加 1 条 `execution` + N 条 `effect`，
  任一笔 `unknown` 即把 `requires_manual_check` 置 true。归档写失败一律吞掉——
  留痕问题不能让已办成的事变成失败。
- `bootstrap` 新增 `build_audit_journal`（默认关闭，未配路径不落文件），`Container` 增加
  `audit` 字段；新增只读接口 `GET /api/ops/audit`（未配置归档返回空列表而非 404）。
- 验证：`pytest` 156 passed / 1 skipped、`ruff` 通过；真实模型（百炼
  `deepseek-v4.1-flash-1017`）下跑通"非幂等工具真实执行 → 归档 1 条 effect + 1 条 execution"，
  `model_calls=2`、工具执行 1 次，文件里查不到敏感入参原文。

## 判断留痕（可复用）

- **"结果未知"必须独立成一类结论**：超时既不能算成功也不能算失败，归档里标 `unknown`
  并置 `requires_manual_check`，否则运维会把它读成"没办成"，然后重复提交一次真实动作。
- **审计只存指纹不存参数**：审计文件要长期保留，写进原始参数等于给自己制造一份
  不受任务级权限管理的数据副本。
- **留痕失败不得击穿执行**：归档写出异常时业务结论必须保持不变（有单测守卫）。
- **并发轮次仍在同一 worktree**：本轮全程在独立 worktree
  （`automation-.../wt-harness-audit`）+ 特性分支上开发，未触碰 worker 的未提交改动。

## 02:50 — 第五轮：取消（cooperative cancellation）

- 新增 `harness/cancel.py`：`CancelToken`（首个原因生效、`Event.wait` 可打断退避）
  与 `CancelRegistry`（按任务隔离、先取消后执行时暂存并在 `begin` 消费、TTL + 条数上限）。
- `AgentLoop.run(cancel=...)`：只在边界生效——`before_model` / `before_tool`
  （模型给出调用清单但工具未动，整批一条不跑）/ `retry_backoff`；已提交的调用跑完并
  照常留痕。新增 `StopReason.CANCELLED`、`EventKind.CANCELLED`（带 stage / skipped_calls）。
- `HarnessExecutor`：`cancellations` 通道；开始前被取消则一步不跑、仍写 trace 与审计；
  执行中被取消 → `unconfirmed` + `cancelled`，**断点保留**（取消的是继续跑，不是没发生）。
- 应用层到执行层的信号：`application/ports.py` 新增 `StepCancellation` 协议（不放 harness
  类型，避免反向依赖），`TaskService.cancel` 在翻转状态前调用它；`Container.cancellations`
  由装配层持有，取消方与执行方共用同一对象。
- 验证：`pytest` 187 passed / 1 skipped（含 12 项新测试）、`ruff` 通过。

## 判断留痕（可复用）

- **取消 ≠ 失败 ≠ 超时**：三者都不能当成功，但取消要保留断点（人取消的是"继续跑"），
  超时要把断点标成不可续跑（外部可能已执行）。
- **不承诺"立刻停"**：同步工具线程杀不掉，硬杀等于把"是否已提交"变成未知；
  对外只说"不会再有新的动作"。
- **取消必须先于状态翻转下发**：状态改了但执行线程不知道，等于没取消。
- **同步执行会吃掉取消**：执行在事件循环里跑时，HTTP 取消请求要排队到执行结束，
  这个部署前提比代码本身更容易踩，已写进 docs 第 14 节。
