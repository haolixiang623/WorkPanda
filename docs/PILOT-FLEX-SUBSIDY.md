# 试点事项：灵活就业社保补贴·材料清单自查

首个真实事项。选它的理由不是它最有用，是它**风险最低而收益可验证**：只读一条口径、
不收集证件信息、不产生任何副作用，但群众拿到的是一份能直接照着准备的材料清单。

代码位置：

| 东西 | 位置 |
|---|---|
| 口径数据与工具 | `src/workpanda/harness/policy.py` |
| 流程定义 | `src/workpanda/infrastructure/pilot_flows.py` |
| 回归 | `tests/test_pilot_flex_subsidy.py` |
| 上线开关 | `Settings.enable_pilot_flows`（**默认关闭**） |

## 1. 它做什么

按群众说的申请身份和手上已有的材料，把办事指南上的材料清单摆出来，逐项指出
"指南要求、但你没提到"的那几项。

## 2. 口径来源

**唯一来源**：苏州市人民政府 · 灵活就业登记服务页

- 地址：`https://www.suzhou.gov.cn/szsrmzf/lhjydj/lhjydj.shtml?para=sjsx`
- 核对日期：`2026-11-09`
- 口径版本：`1`（内容一改就要跟着改，与核对日期一起动）

摘录内容：

| 项 | 原文 |
|---|---|
| 申请对象 | 就业困难人员；离校两年内未就业高校毕业生 |
| 申请材料 | ①身份证；②户口簿；③灵活就业人员社保补贴申请表；④高校毕业生毕业证书（高校毕业生） |
| 补贴标准 | 按照实际缴纳的社会保险费给予 50% 的社保补贴 |
| 补贴期限 | 一般最长不超过 3 年；距法定退休年龄不足 5 年的可延长至退休、最长不超过 5 年；离校 2 年内未就业高校毕业生最长不超过 2 年 |
| 办理渠道 | 江苏省人社网办大厅（选"苏州"）→ 就业创业 → 就业补贴 → 灵活就业社保补贴申领；或江苏政务服务网苏州市站点 |
| 前置条件 | 若以就业困难人员身份申请，需先认定为"就业困难人员" |
| 互斥提醒 | 灵活就业社会保险补贴与失业保险待遇（失业金、失业补助金、失业保险支付的医保待遇等）不能同时享受 |

**该页没有为补贴条款标注文件号**，所以代码里也不补一个——编错的文号比没有文号
更难被发现。需要正式依据请向经办机构索取。

搜索时还会撞到一批第三方转述（各类本地生活号、聚合站），它们补充了"每月 25 日前"
"户籍社区经办""不符合申报的 8 种情形"之类细节。**这些一律没有采纳**：无法追溯
到官方原文的说法，进了签字口径就成了系统在替政府部门立规。

## 3. 三条刻意不做的事

1. **不判断资格。** "你符合申请条件"是经办机构的核定权。输出里只允许出现
   "由经办机构核定"。
2. **不收集任何证件信息。** 清单自查不需要身份证号、毕业证书编号。字段只有两个：
   `applicant_type`（申请身份）、`prepared_materials`（已准备的证明材料）。
   少收一项，就少一条要定留存期限、脱敏策略和删除流程的路径。
3. **不自己复述政策。** 清单由 `policy_checklist` 工具原样吐出，`evidence` 带来源
   地址与核对日期。模型只能引用。

## 4. 为什么加一个只读工具

框架强制执行步骤必须声明工具（`flow_field_errors()`）。但更实质的理由是证据链：
政策类事项如果让模型复述，最先失控的不是措辞而是**来源**——"我记得是这个材料"和
"指南上写的是这个材料"在输出里长得一样，事后没人能分辨。

`policy_checklist` 的性质：

- `risk=LOW`、`idempotent=True`、`timeout=2s`；
- 纯本地字典渲染，**不触网**；
- 参数只有一个 `topic`（enum），**不接受任何个人信息入参**——一旦参数里出现证件号，
  它就会落到工具调用日志、模型请求与审计记录三处；
- 输出确定性：同一输入永远同一字符串，不带时间戳、不带随机 id，否则两次自查会产出
  两份"不同"的证据，回放也就没法比对。

## 5. 上线开关

`enable_pilot_flows` **默认 `False`**。理由与内置网络工具一致：默认不可用比默认
全开安全。一个真实事项"什么时候上线"是运营决定，不该由代码默认值代劳。

- 置 `True`：装配期播种会把发布指针指向 `pilot.flex_subsidy_checklist@1`；
- 置回 `False`：播种**停用**它（清掉发布指针），不是"下次不写入"——上次开着跑过的
  库里还留着指针，只不写入等于关不掉。

与 `enable_demo_flow` 刻意分开：自检流程在正式接入后必须关掉，试点事项要一直开着。

## 6. 验收

`tests/test_pilot_flex_subsidy.py` 共 27 条，按守的东西分四组：

| 组 | 钉住什么 |
|---|---|
| 口径数据 | 来源地址与核对日期必须出现在输出里；材料恰好 4 项，不许"顺手补充"；④ 必须标注仅高校毕业生；输出里必须出现"由经办机构核定"，且不得出现"你符合/可以申请"；两条易漏提醒必须在；渲染确定性 |
| 工具 | 默认注册；参数只有 `topic`；`sensitive_fields` 为空；未知主题被拒并列出可用主题 |
| 流程定义 | 声明的工具都注册过（含反向兜底）；每个必填字段都有中文标签；字段与标签里不许出现证件号；执行指令禁止资格判断；规则指向本版；样例条数达标；**与自检流程同场评测必须 PASS**（防两套规则抢话）；非执行步骤声明 `answer_label` 必须报错 |
| 端到端 | 一句话命中 → 收集 → 确认 → 真执行器 + 真工具跑完 → 办结页**只**拿到 `材料清单自查结果` 这一段，`trace_id`/`tool_calls`/`verification` 一个都不出现；默认关闭时未发布、打开后才发布 |

另有一条相邻事项的负例集：`灵活就业人员怎么参加养老保险`、`我要申请失业保险金`、
`企业吸纳社保补贴怎么办` 都不许被本流程捞走。

## 7. 已知边界

- **口径会过期。** 政策调整后必须人工重新核对来源页、改内容、改 `CHECKED_ON` 与
  `CATALOG_VERSION`，然后发新版本。内置口径通道意味着改一次要发版；事项变多后应
  外置成可运维数据源，但"来源与内容同处一处"这条必须保住。
- **只管材料，不管流程。** 它不会告诉你就业困难人员认定怎么办、去哪里交表、多久
  出结果。这些属于别的事项。
- **不含时间口径。** 补贴自申请当月起享受、断缴补缴后才能发放之类，均未纳入。
- **识别关键词是完整事项名。** 因此"社保补贴怎么办"（少了"灵活就业"）不会被命中，
  会走澄清。宁可多问一句，不要误路由——路由器只做关键词计数，没有"并且"语义。
